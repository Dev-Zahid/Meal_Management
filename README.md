# Meal Tracker (মেস খাতা) — Deploy Guide

আপনার কাছে Vercel, Supabase, আর GitHub অ্যাকাউন্ট আছে ধরে নিয়ে — নিচের ধাপগুলো ক্রমানুসারে করুন। মোট সময় লাগবে ~১৫-২০ মিনিট।

**ফাইল স্ট্রাকচার:**
```
├── index.html            ← পেজ মার্কআপ
├── style.css             ← সব CSS/ডিজাইন
├── config.js             ← শুধু Supabase URL/Key (এই একটাই এডিট করবেন)
├── app.js                ← পুরো অ্যাপ লজিক
├── schema.sql             ← নতুন Supabase প্রজেক্টে একবার রান করার SQL
├── migration.sql          ← আগে থেকে deploy করা থাকলে এইটা রান করুন (schema.sql না)
├── manifest.json          ← PWA ("Install App") কনফিগ
├── sw.js                  ← PWA service worker
├── icon-192.png / icon-512.png / icon-512-maskable.png  ← অ্যাপ আইকন
└── README.md              ← এই ফাইল
```
সব ফাইলই একই ফোল্ডারে/রিপোতে একসাথে থাকা লাগবে।

---

## আপনি কি নতুন করে বসাচ্ছেন, নাকি আগে থেকে চালু আছে?

- **একদম নতুন** → নিচের ধাপ ১-৫ অনুসরণ করুন (schema.sql ব্যবহার হবে)।
- **আগে থেকে চালু আছে (আগের যেকোনো ভার্সন)** → ধাপ ১-২ স্কিপ করুন (Supabase প্রজেক্ট আগে থেকেই আছে), কিন্তু ধাপ ৩-এ `schema.sql`-এর বদলে **`migration.sql`** রান করুন। এতে আপনার আগের সব member/meal/bazar/deposit ডেটা অক্ষত থাকবে, আগের মেসটা নতুন সিস্টেমে `MS-001` নামে যুক্ত হবে, এবং আগের মতোই ফোন+Password দিয়ে লগিন করতে পারবেন।

## ধাপ ১ — Supabase-এ Database বানান (নতুন হলে)

1. [supabase.com](https://supabase.com) → **New Project** — নাম দিন (যেমন `mess-khata`), একটা Database Password সেট করুন, Region **Singapore** বা কাছেরটা বাছুন।
2. প্রজেক্ট রেডি হতে ~২ মিনিট লাগবে।
3. বাম সাইডবার থেকে **SQL Editor** → **New query** → `schema.sql`-এর পুরো কনটেন্ট পেস্ট → **Run**।
   - এটা টেবিল বানাবে: `messes`, `platform_admins`, `members`, `meal_entries`, `bazar_expenses`, `other_expenses`, `deposits`, `managers`।
4. **Project Settings → API** থেকে কপি করে রাখুন:
   - **Project URL**
   - **anon / public** key

> ⚠️ **`service_role` key কখনো ব্যবহার করবেন না** — শুধু **anon/public** key।

## ধাপ ৫ — প্রথমবার ব্যবহার (Setup)

এই অ্যাপে এখন **একাধিক মেস** একই ডেটাবেজে আলাদা আলাদা হিসাব রাখতে পারে। প্রতিটা মেসের একজন **Owner** থাকে, আর পুরো প্ল্যাটফর্ম নিয়ন্ত্রণের জন্য আলাদা একটা **Super Admin** থাকে।

1. আপনার Vercel URL খুলুন — লগিন স্ক্রিন আসবে।
2. **"নতুন মেস তৈরি করুন"** চাপুন → মেসের নাম + আপনার নাম + ফোন নম্বর + Password দিন। আপনি অটোমেটিক সেই মেসের **Owner** হয়ে যাবেন। (ফোন নম্বর সব মেস জুড়ে ইউনিক হতে হবে।)
3. Members পেজ থেকে বাকি সবাইকে যোগ করুন — প্রতিজনের **ফোন নম্বর ও একটা Password** সেট করে দিন (Member এডিট মোডালে)। এটাই তাদের লগিন হবে।
4. Monthly Summary পেজ থেকে প্রতি মাসে কাকে Manager করবেন সেটা assign করুন — সেই মাসে সে অটোমেটিক এডিট অ্যাক্সেস পাবে।
5. (ঐচ্ছিক) লগিন স্ক্রিনের নিচে **"Super Admin"** লিংকে ক্লিক করে প্ল্যাটফর্মের প্রথম Super Admin অ্যাকাউন্ট বানিয়ে নিন — সব মেস এক জায়গা থেকে দেখতে/ম্যানেজ করতে পারবেন। প্রতিটা নতুন মেস "নতুন মেস তৈরি করুন" দিয়ে যে কেউ, যে কোনো সময় বানাতে পারবে।

## Login ও Role সিস্টেম

| Role | কীভাবে পাবে | কী করতে পারবে |
|---|---|---|
| **Platform Super Admin** | লগিন স্ক্রিনের "Super Admin" লিংক থেকে বানানো/লগিন | সব মেসের তালিকা, প্রতিটার মূল হিসাব দেখা, যেকোনো মেস Owner হিসেবে খুলে এডিট করা, মেস ডিলিট করা |
| **Mess Owner** | সেই মেস তৈরির সময় যিনি অ্যাকাউন্ট বানিয়েছেন | সেই মেসের সব দেখা + সব এডিট + Mess Name বদল + Settings |
| **এই মাসের Manager** | Monthly Summary পেজ থেকে assign করা হলে | সব দেখা + Member/Meal/Bazar/Deposit এডিট (Settings/Mess-name বাদে) |
| **বাকি সব Member** | নিজের ফোন+password দিয়ে লগিন | শুধু দেখা (View Only) — সাইডবার থেকে নিজের Password বদলাতে পারবে |

Manager assignment মাস বদলালে (বা নতুন করে assign করলে) অটোমেটিক আপডেট হয়। ফোন নম্বর দিয়ে লগিন করলে অ্যাপ নিজেই বুঝে নেয় সেই ফোন কোন মেসের member — মেস আলাদা করে বাছাই করা লাগে না।

## এই আপডেটে যা যা নতুন যোগ হলো

- **সকাল/রাত এখন Lunch/Dinner**: আগামীকালের মিল জানানোর চেকবক্স দুটোর নাম এখন "Lunch" ও "Dinner" (আগে ছিল সকাল/রাত)। Manager-এর গ্রিডেও এখন "Lunch ✓ · Dinner ✗" এর মতো দেখাবে। **⚠️ `migration.sql` আবার রান করতে হবে** — এটা ডেটা না হারিয়ে পুরনো `sokal`/`raat` কলাম দুটোর নাম বদলে `lunch`/`dinner` করে দেয় (যদি আগে থেকেই migration চালানো থাকে) — কোনো ডেটা মুছবে না।
- **Manager এখন Member Add/Edit করতে পারবে**: আগে শুধু Owner Member ম্যানেজ করতে পারতো, এই মাসের Manager পারতো না। এখন Owner ও এই মাসের Manager — দুজনেই Member Add/Edit/Delete করতে পারবে। Settings ও কে Manager হবে সেটা ঠিক করা এখনো শুধু Owner-এর।
- **মিল জানানোর কাট-অফ সময় এখন কনফিগারযোগ্য**: আগে সবসময় রাত ১২টা ফিক্সড ছিল, এখন Dashboard-এ (মিল-অনুরোধ কার্ডের নিচে) Owner বা Manager নিজেই সময় বসিয়ে দিতে পারবে (যেমন রাত ৯টা)। সময় পার হয়ে গেলে ফর্মটা লক হয়ে যাবে (মধ্যরাতে আবার খুলে যাবে)। ডিফল্ট এখনো রাত ১২টা, বদলানো না হলে আগের মতোই কাজ করবে। **⚠️ এটার জন্যও `migration.sql` রান করতে হবে** (`messes` টেবিলে নতুন `meal_cutoff` কলাম যোগ করে)।

- 🐛 **বাগ ফিক্স — হিটম্যাপে কোন তারিখ বাছা আছে বোঝা যেত না**: Daily Meal Entry পেজের মাসের হিটম্যাপে কোনো তারিখে ক্লিক করলে বা Prev/Next চাপলে নিচের গ্রিড ঠিকই বদলাতো, কিন্তু হিটম্যাপের হাইলাইট (রঙ) সবসময় পুরনো তারিখেই আটকে থাকতো — কারণ ক্লিক করার পর হিটম্যাপটা আর নতুন করে আঁকা হতো না, শুধু পেজ প্রথমবার খোলার সময় একবার আঁকা হতো। এখন প্রতিবার তারিখ বদলানোর সাথে সাথেই হিটম্যাপ নতুন করে আঁকা হয়, তাই বাছাই করা তারিখ সবসময় স্পষ্ট রঙে (সলিড) দেখাবে।
- **আগামীকালের মিল এখন সংখ্যা না লিখে চেকবক্স দিয়ে জানানো যাবে**: আগে মেম্বারকে সংখ্যা লিখতে হতো (১, ২), এখন দুটো চেকবক্স — **সকাল** ও **রাত** — টিক দিয়ে জানাতে হবে। এতে Manager স্পষ্ট দেখতে পারবে ঠিক কোন মিলটা চলবে, কোনটা বন্ধ থাকবে ("সকাল ✓ · রাত ✗" এর মতো ব্যাজ দেখাবে), শুধু একটা সংখ্যা না। ডিফল্ট হিসেবে দুটোই টিক দেওয়া থাকে (স্বাভাবিক দিন ধরে), বন্ধ রাখতে হলে মেম্বার নিজে আনচেক করবে। Manager-এর আসল সংখ্যার সাথে মিলছে কিনা তুলনা আগের মতোই কাজ করে (মোট = সকাল+রাত)। **⚠️ এটার জন্য `migration.sql` আবার রান করতে হবে** (আগের `meal_requests` টেবিলে নতুন `sokal`/`raat` কলাম যোগ করে, নিরাপদ, পুরনো ডেটা মুছবে না)।

- **Owner নিজে Manager না হলে এডিট করতে পারবে না**: আগে যে Owner (মেস তৈরি করেছে) সে সবসময় সব পেজেই এডিট করতে পারতো, Manager না হলেও। এখন এটা ভাগ করা হয়েছে — Meal Entry, Bazar, Other Expense, Deposit-এর মতো দৈনন্দিন কাজ শুধু **সেই মাসের Manager**-ই এডিট করতে পারবে (Owner নিজে Manager না হলে শুধু দেখতে পারবে, বাকি সবার মতো)। Members ও Settings (এবং কে Manager হবে সেটা ঠিক করা) এখনো শুধু Owner-এর — এগুলো মেসের গঠন সংক্রান্ত সিদ্ধান্ত, তাই Manager বদলালেও এগুলো Owner-এর হাতেই থাকে।
- **Inactive Period এখন "organically" পরিষ্কার হয়ে যায়**: কাউকে ১০-১৫ তারিখ Inactive দিলে, ১৬ তারিখের পর Members লিস্টে ওই পুরনো তারিখের ব্যাজটা আর দেখাবে না (মেয়াদ শেষ হওয়ার পর দেখানোর কোনো মানে নেই)। Edit Member খুললেও এখন ফিল্ড দুটো খালি দেখাবে (একটা ছোট নোট সহ, বোঝানোর জন্য কেন খালি) — সেভ করলে ডেটাবেজ থেকেও পুরনো তারিখ মুছে যাবে, আলাদা কোনো ক্লিনআপ চালানো লাগবে না। মেয়াদ এখনো চলছে বা সামনে এমন Inactive Period-এ কোনো পরিবর্তন নেই।
- **Member Ledger-এ Month/Year ফিল্টার**: এখন কোনো member-এর Ledger খুলে নির্দিষ্ট মাস (যেমন আগস্ট) বেছে নিলে শুধু সেই মাসের Meal Entry ও Deposit দেখাবে, সাথে সেই মাসে মোট কত Deposit করলো তার যোগফলও দেখাবে। "সব" রাখলে আগের মতোই সাম্প্রতিক ১০টা এন্ট্রি দেখাবে।

- **আগামীকালের মিল আগে থেকে জানানো (Meal Request) + Manager মিলিয়ে চূড়ান্ত করা**: প্রতিটা মেম্বার এখন Dashboard-এ ঢুকলেই সবার আগে একটা কার্ড দেখবে — "আগামীকাল আপনার কয়টা মিল লাগবে?"। রাত ১২টা পার হওয়ার আগ পর্যন্ত এটা বদলানো যাবে (তারিখটা রোজ এমনিতেই এক দিন করে সরে যায়, তাই আলাদা কোনো টাইমার ছাড়াই কাট-অফ হয়ে যায়)। এখনো না জানালে কার্ডটা লাল/সতর্ক রঙে থাকে — এটাই এখন "আজকের মিল জানান" reminder-এর কাজ করে (নিচে বিস্তারিত)।
  পরের দিন Manager যখন Daily Meal Entry পেজে সেই তারিখ খুলবে, প্রতিটা মেম্বারের নামের পাশে "চেয়েছে: X" ব্যাজ দেখাবে। Manager আসল সংখ্যা বসানোর সময় তা অনুরোধের সাথে না মিললে, সেই মেম্বারের জন্য একটা নোট বক্স খুলে যাবে — **সেখানে কারণ না লিখলে Save করা যাবে না** (যেমনঃ "ও বাসায় ছিল না তাই বাদ")। মিলে গেলে বা কেউ কিছু না জানালে কোনো নোট লাগবে না, স্বাভাবিকভাবেই সেভ হবে।
  **⚠️ এই ফিচার কাজ করতে `migration.sql` আবার Supabase SQL Editor-এ রান করতে হবে** (নতুন `meal_requests` টেবিল যোগ করে, safely বারবার রান করা যায়, পুরনো কোনো ডেটা মুছবে না)।
- **Push Notification নিয়ে একটা সৎ নোট**: সত্যিকারের push notification (অ্যাপ বন্ধ থাকলেও মোবাইলে notification আসা) করতে আলাদা backend (VAPID key + Supabase Edge Function + scheduled cron) লাগে — অনেকটা আগের WhatsApp "Option B"-এর মতোই বাড়তি সেটআপ ও রক্ষণাবেক্ষণের ব্যাপার। তাই আপাতত এটার বদলে উপরের মিল-রিকোয়েস্ট কার্ডটাকেই reminder হিসেবে ব্যবহার করা হয়েছে — অ্যাপ খোলার সাথে সাথেই সবার আগে চোখে পড়ে, না জানানো থাকলে লাল/সতর্ক রঙে দেখায়। সত্যিকারের push notification পরে আলাদাভাবে চাইলে জানাবেন।

- **WhatsApp দিয়ে Deposit জানানো**: Deposits পেজে প্রতিটা এন্ট্রির পাশে এখন একটা WhatsApp আইকন আছে — চাপলে সেই member-এর WhatsApp-এ (তার সেভ করা ফোন নম্বরে) একটা মেসেজ আগে থেকে লেখা অবস্থায় খুলে যাবে ("আপনার XXX টাকা মিল ফান্ডে জমা হয়েছে")। Admin শুধু Send চাপবে। **এটা সম্পূর্ণ ফ্রি** — কোনো backend, টাকা বা Meta approval লাগে না (wa.me লিংক ব্যবহার করে)। মেম্বারের ফোন নম্বর সেভ করা না থাকলে বাটনে চাপলে সেটা জানিয়ে দেবে।
- **Due Reminder WhatsApp বাটন**: Dashboard-এর Due তালিকা ও Monthly Summary পেজে যাদের Due আছে, তাদের পাশে এখন একটা WhatsApp বাটন আছে — চাপলে সেই মাসের Due এমাউন্ট সহ একটা reminder মেসেজ WhatsApp-এ খুলে যাবে।

- 🐛 **বাগ ফিক্স — "সবাইকে ১ Meal দিন" আসলে ২টা করে দিতো**: Daily Meal Entry পেজের দুইটা quick-fill বাটনই ভুলে একই ফাংশন কল করছিল (কপি-পেস্ট ভুল) — "১ Meal" বাটনে চাপলেও প্রতিটা মেম্বারের ২টা করে মিল বসে যেতো। এখন ফিক্স করা হয়েছে।
- 🐛 **বাগ ফিক্স — Meal Entry পেজে Next/Prev বাটনে ভুল তারিখে যাওয়া**: তারিখ পরিবর্তনের কোডে টাইমজোন সংক্রান্ত একটা bug ছিল (`toISOString()` UTC-তে কনভার্ট করে ফেলতো) — বাংলাদেশ টাইমজোনে (UTC+6) এর ফলে Prev/Next চাপলে ভুল দিনে (কখনো ২ দিন পিছনে, কখনো একই দিনে আটকে থাকা) চলে যেতো। এখন লোকাল তারিখ দিয়েই হিসাব হয়, সঠিকভাবে এক দিন করে আগে/পরে যায়।
- 🐛 **জরুরি বাগ ফিক্স — লগিন করার পর ড্যাশবোর্ড ফাঁকা দেখানো / রিফ্রেশ দেওয়া লাগা**: `showApp()` ফাংশন একটা মুছে ফেলা এলিমেন্ট (`ot-dep-mon-f`) খুঁজতে গিয়ে প্রতিটা লগিনেই ক্র্যাশ করত, ফলে ড্যাশবোর্ড/সাইডবার ঠিকমতো লোড হতো না যতক্ষণ না ম্যানুয়ালি রিফ্রেশ দেওয়া হতো। এখন ফিক্স করা হয়েছে।
- **লগিন সেশন এখন মনে থাকে**: আগে অ্যাপ/ট্যাব কয়েক সেকেন্ডের জন্য background-এ গেলেও (মোবাইলে প্রায়ই পেজ reload হয়ে যায়) আবার লগিন করা লাগত, কারণ সেশন কোথাও সেভ হতো না। এখন সফল লগিনের পর সেশন ব্রাউজারে (localStorage) সেভ থাকে — পরের বার অ্যাপ খুললে পাসওয়ার্ড ছাড়াই আগের অ্যাকাউন্টে ফিরে যাবে। "Logout" চাপলে এটা মুছে যায়।
- **সংযোগ হতে দেরি হলে এখন খালি স্ক্রিনের বদলে লোডিং/রিট্রাই দেখাবে**: কয়েকদিন পর প্রথমবার অ্যাপ খুললে Supabase (free tier) কানেকশন কোল্ড-স্টার্ট হওয়ায় লোড হতে স্বাভাবিকের চেয়ে বেশি সময় লাগতে পারে — এটা backend/hosting-এর সীমাবদ্ধতা, ফ্রন্টএন্ড কোড দিয়ে পুরোপুরি দূর করা যায় না, কিন্তু এখন অন্তত স্পষ্ট "লোড হচ্ছে..." মেসেজ ও সংযোগ ব্যর্থ হলে "আবার চেষ্টা করুন" বাটন দেখাবে।
- **প্রতিদিনের ঐচ্ছিক নোট**: Daily Meal Entry পেজে এখন প্রতিটা তারিখের জন্য একটা ঐচ্ছিক নোট রাখা যাবে (যেমনঃ "বাজার হয়নি তাই মিল বন্ধ", "রান্নার লোক অনুপস্থিত") — এটা কোনো নির্দিষ্ট মেম্বারের সাথে যুক্ত না, পুরো দিনের জন্য একটা নোট। **⚠️ আগে থেকে চালু থাকা প্রজেক্টে এই ফিচার কাজ করতে `migration.sql` আবার Supabase SQL Editor-এ রান করতে হবে** (এটা নতুন `day_notes` টেবিল যোগ করে, safely বারবার রান করা যায়, পুরনো কোনো ডেটা মুছবে না)।

## নিরাপত্তা নিয়ে honest কথা

Login পুরোপুরি app-এর ভেতরে (browser-এ) চেক হয় — Supabase Row Level Security পুরোপুরি খোলা (Super Admin-সহ সব টেবিলে)। Password হ্যাশ (SHA-256) করে রাখা হয় প্লেইন-টেক্সটের বদলে, কিন্তু এটা সত্যিকারের bcrypt/Argon2-এর মতো শক্তিশালী না, আর RLS policy খোলা থাকায় Supabase URL+key জানলে কেউ login screen এড়িয়ে সরাসরি API কল করতে পারবে (অন্য মেসের ডেটাসহ)। ছোট মেসের রোজকার হিসাবের জন্য এটা সাধারণত যথেষ্ট। সত্যিকারের সংবেদনশীল ডেটার জন্য Supabase Auth দিয়ে আরও শক্ত করা যায় — দরকার হলে বলবেন।

## Backup
Supabase Dashboard → Database → Backups-এ দৈনিক automatic backup পাবেন (free tier-এও কিছুদিন থাকে)।
